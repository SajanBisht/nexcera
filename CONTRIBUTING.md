# Contributing to Nexcera

## Workflow

1. Pull the latest changes from `main`.
2. Create a feature branch.
3. Make focused changes within your assigned module.
4. Run relevant tests and checks.
5. Open a pull request against `main`.
6. Request review from a teammate.

## Branch naming

- `feat/data-ingestion`
- `feat/model-training`
- `feat/forecast-api`
- `feat/dashboard`
- `fix/cache-invalidation`
- `docs/architecture`

## Rules

- Avoid committing directly to `main`.
- Never commit secrets, raw datasets, or large model artifacts.
- Coordinate shared-contract changes with affected team members.
- Document significant architecture changes.
- Do not claim model performance without reproducible evaluation.
